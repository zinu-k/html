DB 에는 적용하지 않았다. 이 SQL 은 다른 개발자에게 전달한다.

1. 개요 — 무엇을, 왜

TO-BE 패키지(ucare_app_v4.3)의 품질관리(QAS) 테이블 12개는 MariaDB DDL(tb_qas.sql)로만 제공된다. 이 프로젝트는 AS-IS 의 MS-SQL ucare 스키마를 이어 쓰므로(규칙 002 A안), 이 DDL 을 MS-SQL 2022 형식으로 바꾸고 테이블명 접두어를 TB_ → UC_ 로 바꿨다(사용자 요청). 컬럼명은 하나도 바꾸지 않았다.

변환의 기준은 사용자가 정한 원칙 하나다 — 「원본보다 길이·용량이 작아지면 안 된다.」 원본 컬럼에 들어가던 값은 변환본에도 전부, 그대로 들어가야 한다.

핵심 교훈 두 가지.
① 「길이 숫자가 같다 ≠ 용량이 같다」 — MariaDB utf8mb3 의 varchar(40) 은 아무 문자 40글자다. MS-SQL varchar(40) COLLATE Korean_Wansung_CI_AS 는 40바이트(CP949)라 한글은 20자뿐이고, CP949 에 없는 문자(–, ✓, é, NBSP 등)는 오류 없이 ? 로 바뀐다.
② 「이 컬럼은 영숫자뿐이니 괜찮다」는 판단은 앱이 강제하지 않으면 틀린다 — 처음에는 ID·코드·일자 컬럼을 같은 길이 varchar 로 뒀으나, 2차 적대적 검증에서 사용자관리·코드관리 화면이 한글 입력을 막지 않는다는 것이 확인돼 전부 nvarchar 로 바꿨다(3.2).

3.2 왜 문자형이 전부 nvarchar 인가 — 결정 경과

단계설계무엇이 드러났나
1안규칙 002 대로 varchar 유지(같은 길이), 1,000자 이상만 nvarchar1차 적대적 검증: EVL_PLAN_NM varchar(40) 에 한글 21자 이상이 들어가지 않는데 화면이 막지 않음(Msg 2628)
2안한글 명칭 4개만 varchar 2배(40→80, 400→800), 코드·ID·일자·여부 114개는 「영숫자」라 같은 길이덤프 2,579행에서 그 114개 컬럼에 비ASCII 0건이라 안전하다고 판단
반박2차 적대적 검증(반박자 2명)이 판단을 깼다 — 사용자관리 화면의 사용자 ID 입력칸·코드관리의 소분류 코드칸에 영숫자 제한이 없어 원본에는 한글 ID(20자)·한글 코드(30자)가 저장된다. 같은 DB 의 다른 모듈에는 *_CODE 에 실제 한글 값('수리'·'설치')이 있다. 그리고 varchar 118개 전부 CP949 밖 문자가 ? 로 바뀐다 (BMP 전수 스캔: 그대로 17,366자 · ? 45,728자 · 다른 글자 394자). 원본 DDL 을 일회용 MariaDB 에 만들어 대조 재현했다
최종문자형 전부 nvarchar(n)/nchar(n), 길이 숫자 그대로(사용자 결정)엄격 기준 용량 감소 0 · 최대값 적재 36/36 · CP949 밖 문자도 바이트 그대로

// 원본 utf8mb3 varchar(n)/char(n) 은 BMP 문자 n 글자다. MS-SQL varchar 는 CP949 바이트 단위라
// 같은 숫자면 한글은 절반만 들어가고 CP949 밖 문자는 '?' 로 바뀐다(적대적 검증 2차에서 재현).

// MariaDB tinyint(부호 있음)는 -128~127, MS-SQL tinyint 는 0~255 → 음수를 담으려면 smallint.
const TINYINT_TO = 'smallint';

// ---------- 1) 원본 디코딩 (CP949 fatal) ----------
const buf = fs.readFileSync(SRC);

// ---------- 2) 파싱 (모르는 줄은 즉시 실패) ----------
const tables = [];
const blockRe = /CREATE TABLE `(\w+)` \(\n([\s\S]*?)\n\) ENGINE=InnoDB DEFAULT CHARSET=utf8mb3 COLLATE=utf8mb3_general_ci COMMENT='((?:[^'\\]|\\.|'')*)';/g;
const colRe = /^ {2}`(\w+)` (int|smallint|tinyint|decimal|varchar|char)(?:\((\d+)(?:,(\d+))?\))? (NOT NULL|DEFAULT NULL) COMMENT '((?:[^'\\]|\\.|'')*)',?$/;
const pkRe = /^ {2}PRIMARY KEY \(((?:`\w+`,?)+)\)$/;

let m, consumed = 0;
while ((m = blockRe.exec(text)) !== null) {
	const [, srcName, body, tblComment] = m;
	const cols = []; let pk = null;
	for (const line of body.split('\n')) {
		let c;
		if ((c = colRe.exec(line))) {
			cols.push({ name: c[1], type: c[2], p1: c[3] ? +c[3] : null, p2: c[4] ? +c[4] : null,
				notNull: c[5] === 'NOT NULL', comment: unescapeMy(c[6]) });
		} else if ((c = pkRe.exec(line))) {
			if (pk) throw new Error(`PK 중복: ${srcName}`);
			pk = c[1].split(',').map(s => s.replace(/`/g, ''));
		} else {
			throw new Error(`해석 못한 줄 (${srcName}): [${line}]`);
		}
	}
	if (!pk) throw new Error(`PK 없음: ${srcName}`);
	for (const k of pk) if (!cols.find(x => x.name === k)) throw new Error(`PK 컬럼 없음 ${srcName}.${k}`);
	tables.push({ srcName, name: toUc(srcName), comment: unescapeMy(tblComment), cols, pk });
	consumed++;
}
const createCount = (text.match(/CREATE TABLE/g) || []).length;
if (createCount !== consumed) throw new Error(`CREATE TABLE ${createCount}개 중 ${consumed}개만 해석됨`);

	const u = n.toUpperCase();
	if (!u.startsWith('TB_')) throw new Error(`TB_ 로 시작하지 않는 테이블: ${n}`);
	return 'UC_' + u.slice(3);

	const rows = []; let i = 0, row = null, val = '', inStr = false, isStr = false;
